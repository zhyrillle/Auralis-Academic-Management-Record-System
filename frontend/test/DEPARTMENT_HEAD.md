# Department Head monitoring

The dashboard layout reuses the existing six dashboard API calls and metric calculations. Grade comparison uses the shared horizontal StackedBarChart and always includes G7–G10; missing grade rows show "No records". Segments retain actual count labels instead of presenting their drawing widths as learner percentages. The DonutChart and comparison containers share a height, and overview cards use the common StatCard. Submission and performance tables appear in one continuous page. Submission Monitor defaults to five rows with shared pagination and a 5/10/20 row selector. Performance Analysis Matrix retains its original plain columns. Grade Distribution has distinct Score Mean/MPS colors and neutral separators between header groups. The shared FilterToolbar uses term and grade dropdowns and a school-year dropdown without an all-years option; the current or latest available year is selected automatically.

Class Records opens a scrolling section directory first and automatically selects the department's matching subject. It and PHIL-IRI reuse the adviser's ClassCard with the class-type label and editing actions hidden, and add compact learner/adviser details side by side. School-year and grade dropdowns are adjacent. ClassCard's original adviser defaults remain compatible. PHIL-IRI uses common overview cards and the same institutional heading, report header, screening table, post-test table, and reading-level summary components as the adviser. The school seal, official school heading, PHIL-IRI title, gender groups, and screening score boundaries are retained; signatures, the contact/branding footer, and the section/edit/PDF toolbar are omitted from Department Head. Masked LRNs remain, with a wider post-test LRN column that contains the reveal icon. Status is no longer a table column; completeness counts remain in the overview cards. The current read-only class-record renderer, shared grade calculation, term/MAPEH controls, and Excel download are retained. The MAPEH view uses the shared weight resolver for its initial fallback instead of an undefined `DEFAULT_JHS_WEIGHTS.MAPEH` property; backend-supplied weights remain authoritative.

`/api/department-head/monitoring/context`, `/sections`, `/phil-iri`, and `/phil-iri/:sectionId` are additive GET endpoints. Section and assessment reads require a selected school year. They use the existing database-resolved user middleware, require Department Head role and department assignment, and scope offerings to the assigned subject/year. PHIL-IRI requires English. The existing middleware still uses the project's temporary user-id header boundary; this change does not introduce JWT authentication.

Monitoring reads saved database assessments only. No new writes or schema changes are introduced. Adviser screening and post-test saving, draft storage, and authorization are unchanged. Post-test counts describe recorded assessments and do not assert that all enrolled learners require post-tests. Missing tables are unavailable, distinct from an empty assessment list.

The authorized monitoring roster also returns the learner's recorded sex for the shared report grouping. Missing sex is shown as "Sex not recorded", never assigned a default group. If saved learner records contain sex but every row is ungrouped, verify that the updated backend is running, then refresh. Report/context caches are versioned to avoid reusing the older response format without learner sex and school metadata; account isolation and unsent drafts are unchanged. The authorized context reads school heading metadata from the existing SCHOOL configuration. Post-test summaries count saved overall reading levels across the section, not just the visible search. Screening footer totals are explicitly section totals and use each row's saved maxima and score threshold. None of the shared presentation components reads local drafts or performs network requests; adviser-only editing callbacks remain in the adviser page.

Screening column headings show each comprehension area's highest possible score in parentheses, from the section's saved assessment settings. Different recorded maxima display "Varies"; absent settings are blank rather than assumed. Score cells show only the recorded score (for example, 13 rather than 13 / 14), as in the adviser view; totals and post-test raw scores follow the same rule. Missing assessment cells are blank, while genuine zeroes remain visible. Percentages omit unnecessary decimal zeroes, matching adviser display conventions. Assessment Details and Status columns are omitted; completeness counts describe saved record completeness, not academic risk or a reading-proficiency rating. Grade Comparison opts into the shared stacked-chart tooltip, reusing the compact dark tooltip appearance with grade, category, and actual learner count. Mouse hover and keyboard focus show it; leaving the segment, blur, scrolling the chart, or Escape dismiss it. Other stacked-chart consumers retain their existing default behavior.

All new requests and page data use shared account/session-scoped caching. Directory filters are in the URL; returning from a record preserves filters and scroll position. Directories render all matching cards without pagination, and show the section count at the right of the navigation container. Refresh buttons are omitted; browser refresh still requests current records, and failed requests retain retry actions. PHIL-IRI learner tables show all matching learners in one continuous report with male/female separators, no pagination, and horizontal scrolling within the table when needed. System Admin keeps its shared SectionCard. Adviser and Department Head detail headers share the BackButton component and the same icon.

## Deferred existing issues

These are intentionally outside the UI batch and require a separate backend/data review:

- Dashboard quarter filtering references `GRADE_SHEET.term` rather than its term id. School-year choices now use the existing monitoring context; query semantics are unchanged.
- Existing dashboard request failures can be converted to empty data/zero counts.
- Pending submission completion is a fixed 40%; delayed counts are not deadline-derived.
- Reported MPS duplicates average grade. Existing aggregation/denominator semantics need review.
- The dashboard's At-Risk Students count is grade-based, not the English model's prediction count.
- Legacy class-record reads/exports can initialize rows; existing identity/empty-roster fallbacks require a separate review. The new monitoring endpoints themselves execute SELECT statements only.
- Department notifications include legacy demo fallbacks.

## Verification

Run `node --test backend/test/DeptHeadMonitoring.test.js backend/test/PhilIriScreening.test.js backend/test/PhilIriAssessment.test.js` from the repository root. These use database substitutes, not the school database.

From frontend, run `node test/departmentHead.browser.test.mjs` with `PLAYWRIGHT_MODULE_PATH` pointing to the installed Playwright module and optional `BROWSER_CHANNEL=msedge`. The actual application is opened in an isolated browser; all API requests are intercepted with synthetic records and unknown external requests are blocked. Screenshots are written to the temporary artifact directory printed by the test.

The same isolated browser check verifies the adviser's shared report still supports score/maximum editing, autosave, calculations, and its PDF action/footer. Those test writes are intercepted in memory; no school database writes occur. `node test/philIri.test.mjs` also checks shared presentation, summary totals, and account/year-scoped draft behavior.

Also run the existing student-management browser regression (shared card/sidebar), relevant cache tests, changed-file lint, and the frontend build.
